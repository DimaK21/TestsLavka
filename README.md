# Лавка · тестирование магазина

Playwright-тесты и мониторинг учебного магазина `qa-shop` версии 1.0.0.

- [Магазин](http://87.242.119.78:3000/)
- [Дашборд Grafana](http://87.242.119.78:3001/d/qa-shop/lavka)

## Запуск тестов

Нужен Node.js 22 или новее. Распакуйте выданный с заданием архив так, чтобы `qa-shop/server.js` находился рядом с этим README в папке `qa-shop/`.

```bash
npm ci
npm --prefix qa-shop ci
npx playwright install chromium
npm test
```

В Linux для установки системных зависимостей браузера можно использовать `npx playwright install --with-deps chromium`.
Для другой папки с магазином задайте `QA_SHOP_DIR`, для другого локального порта — `QA_SHOP_TEST_PORT`.

Playwright запускает отдельный экземпляр магазина на порту 3100 с временной папкой данных. Каждый новый запуск начинает с исходного каталога. Сценарии получают отдельные браузерные сессии, для регистраций используются уникальные тестовые адреса. Отчёт открывается командой `npx playwright show-report`.

Проверка развёрнутого магазина. Сценарий обращается к health API, читает каталог и открывает карточку товара.

```bash
QA_SHOP_PUBLIC_URL=http://87.242.119.78:3000 npm test
```

## Покрытие

| Область | Что проверяется |
| --- | --- |
| Каталог | Поиск по названию и описанию, регистр и пробелы, пустая выдача, фильтр вместе с сортировкой, товар без остатка |
| Корзина | Добавление из карточки и каталога, пересчёт суммы, сохранение при перезагрузке, удаление и очистка, отказ при превышении остатка |
| Промокоды | `SALE10`, неверный код, сброс скидки, `WELCOME500` ниже порога и ровно на 2 000 ₽ |
| Заказ | Валидация полей, курьер и самовывоз, расчёт доставки после скидки, подтверждение, списание остатка, история заказов |
| Аккаунт | Регистрация, ошибки полей и занятый e-mail, выход, неверный пароль, повторный вход и сохранение сессии |

Результат двух прогонов в Chromium — по 12 успешных сценариев и 4 ожидаемых падения на дефектах ниже. Playwright учитывает `test.fail()` как ожидаемый результат. После исправления дефекта успешное прохождение соответствующего теста подсветит необходимость снять эту отметку.

## Подтверждённые дефекты

### BUG-01 · Заказ принимается с телефоном из одной цифры

**Серьёзность — высокая.** Магазин принимает заказ с номером, по которому нельзя связаться с покупателем, и списывает остаток товара.

1. Добавить любой доступный товар и открыть оформление.
2. Заполнить имя, выбрать самовывоз и ввести в поле «Телефон» строку `+7--- --- -- --`.
3. Нажать «Подтвердить заказ».

**Ожидалось.** Форма показывает ошибку телефона, заказ не создаётся.

**Фактически.** `POST /api/orders` возвращает 201, открывается подтверждение заказа. Проверка засчитывает пробелы и дефисы в длину номера.

### BUG-02 · В карточке можно выбрать количество выше остатка

**Серьёзность — низкая.** Пользователь может выбрать недоступное количество в карточке товара.

1. Открыть «Чайник с гусиным носиком, 900 мл». В исходном каталоге в наличии 3 шт.
2. Выставить 3 в поле «Количество» и нажать кнопку «+».

**Ожидалось.** Значение остаётся равным 3.

**Фактически.** Поле показывает 4 при остатке 3.

### BUG-03 · Гостю видна кнопка «Выйти»

**Серьёзность — низкая.** В шапке одновременно показываются действия «Войти» и «Выйти».

1. Открыть каталог в новой браузерной сессии.
2. Посмотреть на правую часть шапки.

**Ожидалось.** Гостю доступен вход.

**Фактически.** Кнопка «Выйти» видна при `user: null` в `GET /api/auth/me`. Стиль `button { display: inline-block }` переопределяет скрытие кнопки через атрибут `hidden`.

### BUG-04 · При самовывозе видно поле адреса доставки

**Серьёзность — низкая.** Форма просит лишние данные и может создать впечатление, что адрес нужен для самовывоза.

1. Добавить товар и открыть оформление заказа.
2. Переключить способ доставки с курьера на самовывоз.

**Ожидалось.** Поле «Адрес доставки» скрыто.

**Фактически.** Доставка пересчитывается на бесплатную, поле остаётся видимым. Стиль `.form label { display: grid }` переопределяет скрытие через `hidden`.

Запуск только проверок дефектов — `npm test -- tests/known-bugs.spec.ts`.

## Мониторинг

Prometheus опрашивает `shop:3000/metrics` каждые 15 секунд. Grafana получает метрики через внутреннюю сеть Compose. Дашборд показывает доступность сбора, частоту и статусы HTTP-запросов, долю 5xx, задержку p95, заказы, сумму заказов, регистрации, неудачные входы, добавления в корзину, сессии и товары без остатка.

Показатели за 24 часа считаются по приросту счётчиков Prometheus. Сумма заказов включает доставку. Доступ к дашборду открыт без логина с ролью Viewer.

Чтобы поднять такой же стенд, распакуйте приложение в `qa-shop/` и запустите из корня проекта:

```bash
docker compose up -d --build --wait
docker compose ps
```

Магазин слушает порт 3000, Grafana — 3001. Конфигурация источника данных и дашборда подключается при запуске. Данные сервисов хранятся в Docker volumes.
